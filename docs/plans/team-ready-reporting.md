# Team-ready reporting

Status: locally qualified and delivered, 2026-10-09. Owner: phases 03/04/29/31/32 and the existing
Pengui companion. This is the next manual product pass after the locally
qualified [quality continuation](manual-report-product-quality.md); it does not
close phase 34 migration or phase 25 release.

## User outcome

A first-time author creates a useful report from reviewed data, saves and returns,
publishes it for an authorized team, and safely revises it. A separate reader finds
and understands the report on desktop and mobile. The representative acceptance
target is twelve independently authored charts over two pages, with retained
values, filters with explicit applicability, and clear publication/freshness state.
This bounded target is qualified by the local journeys recorded below; it is not
a universal widget limit or full migration parity.

## Delivery stages

1. **Capacity.** Coordinate the issuer, exact dependency projection, verifier and
   immutable envelope bounds. Keep one claim encoding and complete exact scopes;
   never truncate dependencies, substitute wildcards, or infer grants. Preserve
   registered capability scope configuration limits independently of interactive
   projection. Account for MCP's additional action, claim bytes and token bytes.
   Give the self-contained App a measured resource budget with a hard ceiling,
   stable CSP and no runtime code downloads. Retain distinct small viewer limits.
2. **Authoring.** Present data selection, composition, preview and publication as
   comprehensible steps. Preserve explicit source effects, private custody, CAS,
   review and immutable publication. Surface concrete readiness blockers and
   recovery without making users operate internal protocol stages. Keep editing
   responsive, saved state unambiguous and repeated/late actions harmless.
3. **Report quality.** Establish consistent typography, spacing, labels, precision,
   units, empty/error states, filter placement and responsive tables. Provide two
   useful structural starting templates with explicit data mapping. Templates
   never fabricate values, choose unauthorized data or publish content.
4. **Team use.** Improve authorized discovery and the continuity between drafts,
   publication and return-to-edit. Ownership, audience, observation time and
   current publication have distinct meanings. Reuse existing Pengui identity,
   canonical grants and report references; no duplicate report/access database.
5. **Qualification.** Exercise a real PostgreSQL-backed twelve-chart/two-page
   author-to-reader-to-republication journey through both HTTP iframe and
   restricted no-chat MCP. Inspect actual desktop/mobile renders and keyboard
   behavior. Test access withdrawal, stale/expired values, conflicts, interrupted
   effects and retained reads with zero source/model work. Record local latency
   distributions and their fixture conditions, not production SLO claims.

## Private source comparison

User-provided current source trees are inspected read-only. Source locations,
working-tree fingerprints and detailed comparisons remain outside the repository.
Only neutral behavioral requirements and newly authored synthetic regressions
enter implementation. Candidate lessons include type-based field roles, revision
identity, save ordering/recovery, partial loading, effective filter applicability,
and source-preserving query semantics. Each candidate is classified as already
covered, a local fix, a product addition, or separately tracked work. File presence
and predecessor tests are not Chartworks acceptance evidence.
