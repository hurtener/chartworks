# Reviewed learning from service-owned predicates

Status: S10 implementation checkpoint; current exact-head runtime qualification
is pending. Extends [parameterized examples](parameterized-examples-v1.md), not
SQL authority, analytical proof or the approved reporting definition.

## Reusable base, never a historical filter

After the existing feedback action/session/current-source checks and native dry
validation, the service reconstructs the stored clarification/interpretation
binding against current reviewed policy. Only an exact matching binding receipt
can establish its original `BaseSQL` and independent `BaseParameters`. The service
does not parse predicates out of a bound statement or accept a caller-supplied
unbound base. It dry-validates that base against the same reviewed relation scope.

The candidate question is a neutral English/Spanish label with independent
reviewed metric IDs, not the original question, date phrase, answer, period or
model explanation. Known final bindings and active sensitive aliases cannot be
copied into reusable SQL literals/identifiers. The bounded existing disclosure
scanner is reused; unsupported annotations/lexing or too many known spellings
suppress automatic learning while preserving feedback. This is literal-based
protection, not general secret recognition or a license to export source data.

Independent model slots retain only their canonical positions/kinds through the
existing `example-parameters-v1` schema. Service-owned customer/numeric/Boolean
filters and calendar endpoints never become model slots, example defaults or
probe values. The next request computes those predicates afresh through its
current reviewed route. Existing immutable source/context/topic/rule/template
origins and normal native/analytical candidate validation remain mandatory.

## Versioned custody and current applicability

`ExampleOrigin.binding_policy: current-owned-predicates-v1` marks this value-free
base. The digest includes the policy in a separate domain, so changing the base
or its abstract slots cannot reuse the old digest. The existing immutable origin
column/trigger preserves the marker; no migration or retrospective rewrite is
needed. Other examples keep their old digest and rendering.

A marked example is eligible for generation only when the **current in-process
sealed route** resolves at least one owned predicate against the same exact source
binding. The marker itself, retained JSON or an imported row cannot authorize a
predicate. A current unfiltered route explicitly excludes it. No original field,
scalar/time bound or user reach is copied from the example. Different present-day
owned filter types can use the same base when all other origin checks match.

Activation verifies origin, current source reach and the unbound SQL using only
fixed public probes for independent model slots. It neither runs the query nor
calls a model. Probe failures stay failures; old private values are never tried as
a substitute. The reviewed base and marker are serialized as one single-line JSON
demonstration; exact SQL whitespace is preserved. The model is instructed to leave
current service-owned predicates to the binder. Those instructions are advisory;
the binder and native/analytical validators remain the enforcement boundary.

## Portability and deliberate exclusions

Marked portable rows use version 3, whether or not independent model slots exist.
The source origin, binding policy, exact SQL and any value-free slot schema travel
together. Protected import reauthorizes and reroutes its current anchor, requires
current owned constraints, dry-validates the base and creates a candidate requiring
separate review. There is no value-bearing portable extension. The SDK forwards
the same fields through existing authenticated operations and limits.

A reviewer correction of **bound** SQL has no separately authenticated replacement
BaseSQL. Its feedback is recorded but it does not automatically become this kind
of template; explicit protected import supplies a newly reviewed unbound template.
Reference-only selection or unsupported bases are not silently reclassified as
owned-filter templates. Canonical model parameter kinds remain text/integer/number/
Boolean/null; implicit type-dependent conversions that fail public probes remain
unreviewable. This is not arbitrary parameter-domain inference or live engine
qualification. Private/current source permissions are not relaxed for review,
import, consumption or ordinary example listing.

## Required verification

Units cover exact base-proof reconstruction, missing/stale/mutated receipts,
private aliases/literals, cancellation/bounds, portable identity, public probes,
single-lane exact rendering and denial of JSON-origin authority. SDK tests use the
existing authenticated import surface. Real PostgreSQL/recorded-model acceptance
covers current customer replacement, independent model slots, calendar/Boolean/
numeric predicates, review/import, immutable origin, current unfiltered exclusion,
exact result IDs/decimals and zero-work replay. The earlier private-exclusion
regression now checks that only the verified base is exported; annotation and
known-value exclusions remain. Test inventory is not a passing/live gate; the
tracker records observed results separately.
