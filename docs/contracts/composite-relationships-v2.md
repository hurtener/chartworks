# Reviewed composite equality relationships

A reviewed join retains its existing `left` and `right` pair and may add up to
15 `additional_keys` pairs. Every pair names an exact registered column in the
same two ordered datasets. Repeated left/right columns, missing references,
foreign datasets and oversized lists are rejected. There is no SQL condition
string, implicit name matching or permission grant. Candidate/rejected
relationship evidence can retain the same complete key shape without making it
executable.

Compilation canonicalizes conjunction order without changing single-pair legacy
JSON/digests. Clone, mutation/rebinding, dependency/rule closure, topic facets and
portable export/import retain every key. The public SDK exposes
`TopicJoinKeyPair`; ordinary draft review/publication remains the authoring path.

For multi-topic requests, every topic independently confirms the entire key set,
join direction and cardinality. The render-only `confirmed-joins-v2` packet
includes all keys and maps each through the topic's owned physical columns.
Version1 packets cannot carry additional keys. Neither packet proves physical
cardinality or expands the complete validator relation scope.

The analytical compiler emits all paired physical columns. Native SQL must use
exactly those equalities, and source-backed complete unique keys must establish
nonmultiplication for each selected metric population. A matching first key,
metadata cardinality label, prefix index or partial composite key is insufficient.
This also supplies complete keys to independently proved grouped lanes.

Evidence includes catalog bounds/detachment, portable and dataset remapping, rule
closure, independent multi-topic projection and public SDK wire tests. A real
PostgreSQL publication→Plan→Run→restart case produces regional sums30/30 through
a two-column relationship; omitting its second equality is denied, while an
independent source query confirms the malformed join would total120 instead of60.
This increment does not introduce non-equality joins, SQL-authored conditions,
self-join alias policy or null-safe relationship equality.
