# EXP-01 conversational continuity evidence

Date: 2026-09-22. Status: implementation candidate; live calibration and final release qualification remain open.

The governed comparison found one concrete runtime gap: additive refinement could add semantic references and pinned metrics but could not express exact removal or replacement. That could retain an earlier dimension or metric after an explicit follow-up. The implementation adds closed, bounded reference and metric edit contracts while retaining the existing clarification-answer and interpretation-edit contracts for corrected/removed filters. The post-review fix rejects unpaired measure/KPI and metric-ID deltas before routing/provider work, sorts the final references by full typed coordinate and metric IDs lexically, and uses that canonical form for routing, generation context, digesting and persistence.

The service now walks protected query ancestry before every refinement. It accepts at most sixteen children, denies cycles and cross-session/cross-context ancestry, and returns `new_question_required` when a fresh question is needed. Each child records the exact observed parent revision and protected-record digest. Migration 049 makes those coordinates immutable and the PostgreSQL create transaction locks and rechecks the parent, so a concurrent update cannot commit a stale fork. Current semantic publication is still an execution boundary: a republication makes refinement return `context_changed` rather than silently translating old intent. Every accepted child still passes current topic/source/context admission, gateway authorization, context assembly, native validation and protected persistence.

Focused unit tests cover add/replace/remove semantics, absent and duplicate targets, paired metric/reference coherence, permutation-equivalent route inputs, stale parent fencing, bounded/cyclic/foreign ancestry and public error classification. The real PostgreSQL acceptance journey covers English and Spanish questions, rejects an unpaired metric replacement without a model request, verifies persisted parent revision/digest evidence, rejects a child after a concurrent parent update, covers dimension add/remove and metric replacement, rejects cross-session/context reuse and verifies a v1-to-v2 semantic republication fence. Phase 24 fixture cases add protected bilingual evidence for add dimension, replace/remove filter, metric change, clarification correction and semantic republication. Existing CW-01 and CW-07 acceptance remains the runtime evidence for typed clarification and interpreted-filter correction/removal.

Local verification used `CGO_ENABLED=0` because the checkout does not contain the optional native Bruin archive. The NLQ core/API/SDK tests and acceptance compile gate pass. The real PostgreSQL journey requires the configured test store and is left to hosted CI; no missing database was reported as passing evidence. Live approved-model comparison, owner-calibrated source snapshots, cost/latency measurements and final cross-system evidence remain Phase 34/25 work.
