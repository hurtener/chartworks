in [the characterization](scalar-predicate-characterization.md), not recovered
historical capability. The governing contract is
[exact scalar predicate entailment](../contracts/analytical-scalar-entailment-v1.md).
Recorded model responses supply reproducible generated SQL; they do not establish
live-provider quality, hosted CI, release readiness or support for other engines.

## Scope and source checkpoints

The extension uses analytical-metrics-v13, protected binding schema 6 and
entailed-scalar-predicates-v1. It proves canonical exact native-text equality for
every SUM/COUNT expression occurrence of every selected scalar root, on the
already qualified v9 fact-owned period shape. No constraint is dropped and no
predicate is propagated into generated SQL. Finite sets, ranges, arbitrary Boolean
logic, LEFT joins, grouped outputs and other engines remain outside admission.

## Proof and refusal controls

Compiler and execution tests cover complete constraint-by-occurrence coverage,
repeated measures under different inherited KPI filters, selected COUNT roots,
missing/repeated leaves, unfiltered or differently filtered COUNT companions,
NULL/inexact/unsupported metadata, and bounded traversal/product overflow.
Selected semantic identities and exact reviewed relationship choices are tested
independently from physical SQL, including owner substitution with identical
physical filters and relationship substitution with identical physical edges.

Physical controls include missing joins, excluded JoinChoices, complete composite
key requirements, swapped/partial pairs, type-compatible full-key substitution,
current source binding, and actual PostgreSQL uniqueness removal/restoration.
A valid identical field name on another fact passes generic constraint validation
and is then specifically refused as analytical_scalar_predicate_not_entailed.
No broad missing-field rejection stands in for that distinction.

Receipts/effects are tested for missing, duplicate and extra constraints, explicit
zero-parameter effect cardinality, changed coverage and occurrence counts, output
ordinals and detached-base binding. Attacker-controlled hashes are recomputed in
forgery tests; public hashes cannot manufacture semantic/current-route authority.
V1-v12 reject new-only entailment contract/receipt/effect fields, including a
present empty effect list. Deep copies preserve request-local proof immutability.

Original-operation Plan replay preserves its older pointer contract: exactly the
same QueryID/SessionID, no SQL or proof exposure, and no gateway/result work.
Same-actor changed input refuses; different actors retain distinct private
operation namespaces. This pointer-only replay is not a new result admission.

work. Removing the selection yields the existing v9 path; replacing it with a
non-entailed value refuses before SQL generation; changing periods creates a
fresh v13 child that passes its independent source oracle and terminal replay.

a fresh current query is established before testing source revision rotation.

schema 6.

One earlier lifecycle run found a real Refine gap: swapped output ordinals reached
one routing gateway call before refusal. The eight-line v13-only repair in

## Context format stability and legacy compatibility

An independent mandatory-context issue appeared during native qualification:
legacy activity context could exceed the unchanged 6,500-token tier, and later
provenance-dependent fixtures fit at 6,494 and 6,473 tokens. This was not treated
as stable headroom. The separately committed presentation change uses an explicit
shared-versioned-v2 metric wrapper while omitted format reconstructs exact legacy
shared and nonshared bytes. The detailed contract is
[generation packet v2](../contracts/generation-packet-v2.md).

V2 retains every raw body byte, typed versioned namespace, selected root and
ordered dependency edge, using explicit raw-body byte lengths. No body is parsed,
shortened or removed. Unit tests independently decode the complete graph, cover
conflicts/foreign namespaces/delimiter-like bodies, verify old prompt/JSON/seal
and query-lineage goldens, and exercise projection, provider refit, reseal and
unknown-version refusal. Concurrent legacy/v2 rendering is race-tested without
mutating source inputs. An adversarial 64-hex provenance value tokenizes to one
token per character: the same synthetic six-leaf graph measures 6,531 legacy
versus 6,297 v2 tokens under the unchanged 6,500 cap. Oversized mandatory bodies
still produce typed whole-context refusal.

Native legacy compatibility is deliberately synthetic persisted evidence. Before
its first PostgreSQL insert, a test repository wrapper invokes the production
omitted/v1 assembler on a normally admitted query and verifies SQL, parameters,
receipts, selected meaning, publication/source pins and operation identity remain
unchanged. It neither updates immutable rows nor disables storage guards. Normal
restarted production services then prove SDK Run, terminal replay, pointer-only
original Plan replay and Refine. In the corrected fixture, a 6,033-token legacy
shared context retains exact stored JSON and lineage; terminal replay does zero
gateway/result work; the new Refine child uses explicit v2 at 5,879 tokens without
rewriting its legacy parent. This is not a recovered old production artifact.
