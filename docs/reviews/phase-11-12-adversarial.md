## Preserved boundaries

Pengui remains the only issuer and policy owner. No new credential issuer, identity model, ambient authorization, alternate query engine or learned-model client is added. Uploaded data still uses the same source registry, signed execution-context reach, opaque validator plan and bounded executor. Optional summaries still use the existing gateway; deterministic profiling does not require a model.

Request work continues to use the existing operation ledger and lease/fence mechanics. A retry supplies current caller authority and preserves the accepted input. A cancellation request, an uncertain external commit, a loaded workspace receipt and a completed metadata publication remain different facts. The new publication callback and erasure cleanup do not make external effects exactly-once.

Erasure here means logical removal from the live workspace and live derived-profile storage, with minimal immutable manifests/tombstones retained for safety and replay handling. It does not claim secure overwriting of database pages, WAL, snapshots or backups. Backup retention and physical erasure are deployment responsibilities. Source operators with administrative database access are not made cryptographically incapable of altering their database.

Profiles remain evidence, not published business meaning. The later semantic and reporting consumers must close their integration boundaries in their own phases before migration/release acceptance. This PR does not ship those later phases merely by exposing an inspection or dependency-registration seam.
