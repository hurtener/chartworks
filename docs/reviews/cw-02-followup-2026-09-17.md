## Findings fixed

### P1: typed-equal hierarchy parents produced unreadable retained trees

Coordinate identity correctly groups equivalent numeric spellings and temporal
instants, but descendants previously retained different raw parent spellings.
The viewer requires each child path prefix to equal its actual parent path, so a
valid built tree could fail closed in the real consumer. Shared nodes now supply
the first ordered observed spelling to descendant drawing paths. Exact original
spellings remain unchanged in retained wide rows and their original row indices.
Leaf identity, exact aggregation and duplicate-leaf rejection are unchanged.

`TestCW02HierarchyEquivalentParentLabels` checks numeric and temporal aliases,
parent/child and point/node consistency, exact totals, unchanged source rows and
typed-equal duplicate rejection. The new `hierarchy_equivalent_parents` fixture
also enters the existing save/read/build and actual Chromium component suites.

### P2: custom hierarchy ordering bypassed the declared prefix contract

Explicit and saved mappings admitted a measure-first, child-first, skipped-level
or interrupted hierarchy order, despite the current shared contract requiring the
root-to-leaf prefix. Validation now checks that prefix for both bind and build.
A proper partial prefix, complete prefix, mixed ascending/descending directions,
and a measure after the complete path remain supported. Default order is unchanged.

`TestCW02HierarchyOrderPrefix` exercises all these positive/negative cases and
checks that editing a saved mapping cannot bypass the same validation.
