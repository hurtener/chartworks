## Outcome and causal baseline

Demonstrate one complete scoped path:

**profile and business context → generated/enhanced draft → complete-topic quality
review → explicit publication approval → current learned context → correct NLQ**.

Existing reviewed SQL examples, exact topic publication and semantic dependencies
are real consumers. They do not alone demonstrate topic-meaning learning. The
earlier live Commerce diagnostic used manually authored topics and `SkipLLM:true`;
its six failed SQL plans did not measure enrichment. Its subsequent one-case trace
shows the reviewed temporal dimension in context but no corresponding calendar
proof guidance for “by month”; model generation and repair therefore disagree
with the compiled intent. Fix and measure this linkage rather than weakening
source or semantic validation.

## Ordered implementation and exit gates

### 1. Preserve useful feedback and retrieve eligible learning

- Persist authorized negative observations even when retained SQL cannot be
  validated. Keep cancellation/access denial distinct. Invalid SQL supplies no
  executable plan, approved example or topic mutation
- Filter active/reviewed, locale/context/topic/source/rule/template-current
  examples before candidate truncation; use bounded query-aware retrieval and
  deterministic ordering. Retain exact applicability checks at the consumer
- Prove that 64 stale/high-weight/candidate rows cannot hide a relevant eligible
  example, and that it reaches the rendered prompt, not just a selection list
- Preserve idempotency, current-source native review, value-free parameter
  templates, private current values and explicit activation

Exit: actual PostgreSQL feedback/dedup and starvation regressions, negative
cross-actor/source cases, and actual rendered/omitted example-use receipts.

### 2. Build the complete authoring packet and relationship coverage

- Supply the topic's stated business meaning, descriptions, existing semantic
  definitions and exact authorized profile provenance to enhancement
- Include bounded sensitivity-safe aggregate evidence; exclude raw rows, private
  values, credentials and historical defaults. Every field has an explicit
  provenance and omission/coverage disposition
- Resolve relationship candidates against a bounded complete authorized column
  catalog rather than requiring both endpoints in the same 32-column page
- Apply one effective gateway-envelope bound. Missing mandatory context remains
  unresolved; do not silently truncate it or invent meaning

Exit: captured structured gateway packets prove context is consumed; privacy,
foreign/stale profile and budget negatives pass; page size/order does not change
which legitimate cross-page relationships can be proposed.

### 3. Make whole-topic semantic review a consumed workflow

- Review the complete candidate against its exact digest and evidence coverage
- Produce closed advisory findings/unresolved states; do not edit protected
  structure or let model confidence authorize publication
- Persist the report with the generation checkpoint and consume it in the
  generated-topic review/publication path. Keep manual/legacy policy explicit
- A changed draft/profile invalidates the report. Failed final review leaves the
  prior durable checkpoint intact; human approval remains a separate operation

Exit: alias collisions, temporal/grain contradictions, incomplete coverage,
model structural edits and stale reports are exercised through the real workflow;
reviewed publication and index generation bind the same approved revision.

### 4. Close intent and meaning-learning loops

- Resolve “by month”/“por mes” only to a uniquely supported reviewed temporal
  dimension/grain within the selected metric context. Preserve its time basis
  and source identity. Ambiguity clarifies instead of choosing a different date
- Carry that exact grouping contract into prompt, native proof, repair and replay
- Add an explicit correction-to-topic/rule **proposal** consumer with before/after
  evidence, closed edit scope, exact source/topic origin and human review. No
  feedback event or successful SQL silently rewrites semantic meaning
- Reindex only the reviewed semantic revision and prove later held-out phrasing
  consumes the approved change. Never turn old private literals into new defaults

Exit: durable proposal→review→publication→reindex→later prompt/results, with
no mutation before approval, foreign/stale/replay negatives and current-value
privacy. This is additional topic-learning scope, not retroactive closure of the
previous template/domain checklist.

## End-to-end qualification

Keep source snapshot, questions, locale/anchor, authority and independently fixed
expected values constant. Compare (A) manual topics without examples, (B) generated
and enhanced reviewed topics, (C) those topics with reviewed learning, and (D) any
necessary proof-consumer fix. Observe exact topic/profile/review digests, current
selection, rendered context, actual example use, bounded synthetic candidates,
closed repair codes, opaque plan and final rows. Passing SQL syntax is insufficient.

Start with recorded-provider transport/lifecycle tests and real disposable
PostgreSQL/MySQL. Then run one authorized live synthetic cohort with the selected
models and shared monetary cap; only its exclusive executor can spend. Never
claim recorded tests as live model quality. No customer data or credentials enter
repository/evidence artifacts. Implementation completion depends on these exit gates, not on an invented
percentage or a promised clock time.

## Deliberate boundaries

Exact numeric tolerance, externally asserted physical uniqueness and arbitrary
SQL normalization breadth remain separate architecture decisions. They do not
block the scoped topic milestone and cannot be relaxed to make it pass. Existing
source authority, private binding custody and discovered group-domain correctness
obligations remain enforced throughout.
