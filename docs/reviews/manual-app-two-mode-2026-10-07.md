# Manual report App: both-mode local qualification

2026-10-07. This records the real isolated Docker candidate, not a production
activation, whole-product release, hosted CI result or paid model measurement.
The owner requested local testing because Actions billing prevents jobs starting.
Work and bounded adversarial review were performed without subagents.

## End-to-end evidence

The same native report application ran inside the actual Pengui Apps shell in
registered HTTP iframe mode and restricted no-chat MCP mode. Each final journey
created its own “October revenue review”, selected the named Commerce topic,
Sales dataset and Revenue measure, prepared a KPI, added Analysis and Notes pages,
saved, left the App, reopened the private draft, validated data, ran a private
preview, published the whole chart revision, rebound the report, submitted review
and explicitly published report revision 2. A separately invited ordinary
Consumer opened the named published report, its exact retained value and Notes.

Each mode passed 17 browser checks (creation 5, preview 4, publication 4, Consumer
4), plus 14 independent Consumer API checks. Screenshots were inspected at 1440
and 375 pixels using sandboxed Chromium 148.0.7778.96. No provider responses were
intercepted. Exact retained value `9007199254740998.625` survives both modes,
publication and reload; display formatting does not replace the exact value.
The Consumer cannot edit, publish, execute, read the Builder's private preview or
guess a run. Context withdrawal removes catalog/history/read; restoration requires
current admission. Same-key published execution returns the original run.

Additional real MCP checks passed:

- Chart catalog/copy/formatting: 11 API checks and 3 browser checks. Published
  source metadata and earlier retained values remain unchanged; stale CAS and
  missing source/parent/allocation authority deny. An API-created private amendment
  was the setup for this chart-editing probe, not proof of a published-edit UI.
- Governed options: a separate real PostgreSQL regional fixture, 10 API checks
  and 3 browser checks. Exact dataset search, opaque pagination, original-key
  custody, altered-input conflict, explicit current-source permission, saved
  report bindings, later-draft recovery and retained original values passed.
  Typing, page changes, saving and reopening do not trigger another Search.
- Lifecycle: 12 checks cover nonce, foreign origin, another canonical login for
  the same user, changed catalog generation, tampered admission, closed tool list,
  close/reopen, host generation, document digest and logout. An additional actual
  five-minute expiry check rejects document and callback access. Changed catalog
  generation currently yields a generic 503; tampered admission yields typed 409.
  Neither exposes result content. More precise stale-generation wording is debt.

The initial options probe correctly rejected Region against the non-regional
fixture. It was rerun against the existing regional fixture, without relaxing
validation. Model services were disabled. Physical source work occurs only for
explicit preparation, validation, preview, published execution and option Search;
retained UI navigation does not dispatch those operations. Fixture completion
counters and actual wire paths are retained with the private local evidence.
Both fixture holds completed normally: exact-value campaign 22 source attempts,
regional campaign 7, and zero model calls in each. These totals include the
explicit setup journeys within each live campaign; they are not per-report costs.

## Integration corrections found by real execution

1. Canonical signed capability activation uses a sole `capability:connect` service
   bearer for static MCP discovery. Chartworks now accepts that exact verified
   profile only for initialization/ping/static inventories. Calls and every
   resource read still deny. D-104 and the MCP contract pin this narrow exception.
2. Manual-report callbacks now carry MCP Apps visibility metadata. Static tool
   inventory alone did not make them callable from the existing App host. Actual
   factory inventory tests cover the full callback list and exclude unrelated
   query execution; metadata changes do not grant domain authority.
3. Each native MCP callback receives `mcp.use` plus independently projected domain
   scopes. Generic broker credentials remain denied for App-governed capabilities.
4. The existing AppBridge client unwraps the native result envelope exactly once.
5. The Pengui BFF checks native dependency policy before dispatch and again before
   releasing results. Broker-side projection remains independently mandatory.
   The late-withdrawal regression reproduced a 200 exposure before this fix and
   now denies; the denied-before-dispatch case makes zero Protocol calls.

MCP uses the existing runtime Protocol, canonical agent activation, physical source
lookup, fresh sealed render admission and broker exchange. The real 261,609-byte
HTML was resolved through identity-bound `artifact_ref` windows with exact digest
and length checks. No conversation or model was opened. Four central catalogs
(drafts, topics, published reports, runs) deliberately keep the same BFF-owned
provider-native HTTP composition in both modes; 28 callbacks use MCP in MCP mode.
This is not a claim that every catalog request is an MCP tool call.

## Local gates and delivery boundary

- Pengui final focused HTTP/Protocol race selection: 11.197s / 1.576s, passed.
  In-memory, SQLite and actual PostgreSQL operation-intent/MCP-host/migration
  selections passed (1.734s / 33.983s / 11.223s), with no skipped store boundary.
  The single-use operation race includes 128 concurrent attempts.
- Frontend focused suites, production build, Svelte check (zero errors/warnings),
  direct MCP client tests and changed-file lint passed. Live probes exercise the
  served build; evidence records HTTP versus MCP wire transport explicitly.
- Chartworks reference Linux race tests passed for MCP, reporting API, topic API,
  chart API and actual factory inventory. The real PostgreSQL phase22 discovery
  acceptance passed (22.680s). Planning and mirrored rules checks passed.
  The macOS native-link attempt lacked the native signatures library; the Linux
  reference checks are the passing evidence, not that failed local attempt.
- Runtime full drift/preflight evidence is recorded in its companion PR. The
  integration does not replace that repository's required before-commit gates.

The final direct review covered exact dependency projection, operation custody,
cache/retry exclusion, current activation/configuration, document/artifact bounds,
private/public separation and result exposure. No unresolved P0/P1 is known in
this bounded slice. Existing whole-product phase release obligations remain.

Known UI follow-up: after closing a published report, the Builder catalog lists
private drafts/reviews and has no “Edit published report” entry. Native exact
revision amendment works, and an already-open Builder can save an amendment.
This acceptance proves private-draft reopen and published Consumer reopen; it
does not claim a fresh published-to-Builder entry point. Retained widget bodies
scroll when their saved grid height is smaller than provenance/table content.

Draft PRs remain unmerged. Production is unchanged. Upgrade/activation requires
compatible commits, exact document digests, canonical policy and the runbook;
existing installations do not silently opt into MCP. The persistent local
walkthrough contains actual screenshots, results and final companion identities.
Cookie, token, DSN, key and private session files stay outside source control.
